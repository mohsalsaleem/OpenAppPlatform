# v0.1 standalone release boundary

The product is a multi-component application on one server, operated through
documented interfaces by an owner-authorized external agent. The owner establishes
trust; the agent never owns bootstrap credentials or writes OAP's control database.

## Remaining implementation order

1. Pre-deploy jobs: image-defined migration process, bounded observation,
   release-local completion evidence, dependent workloads blocked on failure,
   and observation-only recovery after interrupted dispatch.
2. Basic app-wide image rollback: restore a preceding successful release's owned
   workload images together, preserve application data and volumes, and never run
   implicit reverse migrations. Explain incompatible topology/configuration
   instead of pretending an image rollback restores them.
3. Release acceptance: one named-agent CLI journey creates a reference app,
   deploys it, runs a migration, scales routed replicas, diagnoses an injected
   failure, corrects it, rolls back workload images and verifies app behavior.
   Retain API/MCP contract coverage and the existing crash/rescue/install checks.
   Run the exact-tree local gate before commit/push; Git CI remains disabled.

Acceptance retains Caddy HTTPS, app-local networking, declarative components,
secrets/volumes, reviewed addition/removal, structured operations, logs and scoped
diagnosis. Standard deployment may cause downtime. Public certificate issuance
has historical VPS evidence; observing a scheduled renewal is a separate follow-up.
Basic backup/recovery procedures remain required; automated application-data
backup/restore does not become a release prerequisite.

## Post-v0.1

Definition history/revert/export; previews; declared application-check workflows;
guarded rollout and automatic rollback; promotion policy; environment comparison;
expanded GitHub/build integration; Compose import; automated pruning/retention and
volume backup/restore; additional operator/UI work; deeper routing hardening.

The [older baseline acceptance](v0.1-acceptance.md) records historical scope and
receipts. Those receipts do not certify the new standalone release tree. This
document and the roadmap's v0.1 boundary govern the remaining release work.
