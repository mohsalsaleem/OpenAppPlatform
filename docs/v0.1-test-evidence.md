# v0.1 test evidence

This page maps the [v0.1 standalone release boundary](v0.1-standalone-acceptance.md)
to the tests that already exercise it. The exact-tree local gate (`make test-local`,
driven by `tests/env/run.mjs`) runs all of them and writes machine-readable
receipts to `OAP_TEST_REPORT_DIR`. Receipts and gate IDs are kept privately by
the harness; record the gate ID here when a release candidate passes.

## Coverage of the v0.1 journey

The release boundary asks for one named-agent CLI journey that creates a
reference app, deploys it, runs a migration, scales routed replicas, diagnoses an
injected failure, corrects it, rolls back workload images and verifies behavior.
Every step is covered today, but **across several tests rather than one
continuous journey**:

| Journey step | Covered by | Receipt |
|---|---|---|
| Owner bootstrap, named-agent grant, create app | `tests/env/headless.py`, `tests/env/dogfood.py`, onboarding system test | `headless-acceptance.json`, `dogfood-acceptance.json` |
| Deploy with a pre-deploy migration job | `TestStandaloneDockerRunToCompletionPrimitive` → `named-agent-release` | `pre-deploy-jobs.json` |
| Failing migration blocks rollout; incident shows it | same | `pre-deploy-jobs.json` (`nonzeroExitBlocksRollout`) |
| Routed replicas through Caddy, scale 1 → 3 → 1 with traffic checks | `TestAgentStandaloneIngressReleaseScaleAndControllerRecovery` | `ingress-lifecycle.json` (`scale`, `scaleDownFailures`) |
| Traffic continues while the controller is down | same | `ingress-lifecycle.json` (`controllerDownTraffic`) |
| Add web/worker, reviewed removal, data kept on re-add | `TestAgentAddsRemovesAndRestoresStandaloneComponents` | `topology.json` |
| Diagnose an injected failure, correct, verify behavior | `tests/env/dogfood.py`, `TestIncidentProjectionScopeRedactionBoundsAndUncertainRecovery`, native health-check incident test | `dogfood-acceptance.json`, `incident-acceptance.json` |
| App-wide image rollback, migration not re-run, volume data kept | `named-agent-release` | `pre-deploy-jobs.json` (`appWideWorkloadImageRollback`, `migrationSkippedOnRollback`, `volumeDataRetained`) |
| Routed rollback while sibling routes stay live | ingress lifecycle test | `ingress-lifecycle.json` (`routedAppImageRollback`) |
| Lost responses recovered by observation, never re-dispatched | pre-deploy jobs and ingress lifecycle tests | both receipts |
| Install, update, crash/rescue, metadata restore | `tests/env/dogfood.py`, `tests/env/installation.py` | `dogfood-acceptance.json`, install receipt |
| Public HTTPS (Let's Encrypt) | Vultr acceptance at `bac0f62` | see public acceptance doc |
| Footprint (OAP, PostgreSQL, Caddy) | `tests/env/footprint.py`, `tests/env/ingress_footprint.py` | `footprint.json`, `ingress-footprint.json` |

## Gaps

- **No single continuous journey.** The steps above run against different
  fixtures. The remaining v0.1 work is one script that chains them against the
  same reference application (see the roadmap's v0.1 closeout).
- **Gate ID for `3ac90b1`** is not recorded in the repository.
- **Public ACME on the release tree.** The Vultr run was at `bac0f62`; later
  ingress commits have local-CA coverage only.
- **Scheduled certificate renewal** has not been observed.
