# v0.1 Release Candidate Notes

Open App Platform runs a multi-component application on your own server, operated
through scoped machine interfaces by your agent. Standalone Docker is the primary
v0.1 path; existing Coolify compatibility preserves native ownership. No AI model, builder, registry,
logging cluster or additional identity service is required for core use.

Remaining release gates follow the [standalone v0.1 boundary](../v0.1-standalone-acceptance.md),
not every M3 roadmap item. A fresh exact-tree local gate is required for this candidate.

## Included

- Owner setup/sign-in, invite-only workspace access, scoped and revocable agents,
  action/target/environment restrictions, and durable operation audit correlation.
- Discover and group existing resources without restarting them; inspect health
  and bounded masked logs. Native source builds and GitHub triggers remain native.
- Managed image web/worker components, explicit connections and linked existing
  database dependencies, selected releases, readiness, restart, supported scaling,
  retained bindings and exact-operation recovery.
- Docker CPU/memory limits, retained single-instance named volumes, private pull
  references and no-new-privileges defaults with human-owner exceptions.
- Caddy app-domain/path routing, optional public Let's Encrypt, replica scaling,
  and routes that keep serving while OAP is stopped.
- Specification-driven component addition and reviewed removal.
- Pre-deploy image jobs with exit evidence and observation-only recovery.
- Basic app-wide image rollback, skipping jobs and retaining supported named volumes.
- Versioned configuration/release comparisons.
- Packaged owner installation, external controller recovery, quiesced metadata
  backup/isolated restore and owner-visible backup reports.
- Optional encrypted host-file secrets with exact grants and original-key recovery.
- Bounded deterministic release/change context and durable local outcome events.

## Installation and Update

Follow [installation](../installation.md), then the
[four-component example](../../examples/application-breadth/README.md).
For existing Coolify resources start with discovery/grouping; for standalone
Docker follow [the socket and ownership guidance](../bare-docker.md).

Use an immutable controller image and a verified private metadata backup before
updating. Check schema and semantic compatibility before controller rollback;
SQL downgrade is unsupported. Keep target configuration, credentials, encrypted
store and original key separately. Metadata restore does not restore workload
databases or volumes. Never activate an arbitrary stale backup over live bindings.

## Known Limits

Standard replacement can cause downtime. Blue-green/rolling strategies, previews,
guarded rollout and automatic rollback remain deferred. Installed domain/port
authority handoffs and extended draining are later routing hardening. Caddy renewal
is automatic; a scheduled renewal has not yet been observed in acceptance.
Coolify source resources and linked databases retain native lifecycle/configuration
ownership. Additional operator adapters, multi-server placement, alternate runtimes,
indexed logging, AI diagnosis and remote-agent access are outside this release.

Notification events are local only; external delivery is disabled. No telemetry
or inference is required. Secret changes require a reviewed controller restart;
no secret rotation or external vault provisioning is provided. Container policy
does not imply mandatory non-root workload images, scanning/signing or protection
from host/operator image pruning. Resource measurements are recorded in the footprint report. The measured combined
idle CPU goal is not met; it remains disclosed post-v0.1 optimization work.

See [acceptance and evidence](../v0.1-acceptance.md). No release tag or production
promotion is implied by these candidate notes.
